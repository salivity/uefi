Maximum Partitions on a GPT Disk in UEFI Systems

Under a standard GUID Partition Table (GPT) disk layout on UEFI systems, the default maximum limit is 128 partitions. This article covers the technical specifications defining this 128-partition threshold, the mathematical allocation behind the partition table, how modern operating systems implement it, and how it compares to older partition schemes.

The 128-Partition Standard Explained

The UEFI specification requires that a GPT disk reserve a minimum of 16,384 bytes (16 KB) of disk space for the Partition Entry Array. Each partition entry in this array requires exactly 128 bytes of data to store partition metadata, such as unique GUIDs, start and end Logical Block Addresses (LBAs), and partition attributes.

Dividing the reserved space by the size of a single entry establishes the standard limit:

\[16,384 \text{ bytes} \div 128 \text{ bytes per entry} = 128 \text{ partitions}\]

Because this 16 KB allocation is placed immediately after the primary GPT header (starting at LBA 2 on standard 512-byte sector drives), operating systems conform to this boundary to maintain compatibility across different UEFI implementations.

Windows and OS Implementation Limits

While the GPT specification technically allows a disk partitioning utility to allocate more than 16,384 bytes for the partition array—theoretically enabling thousands of partitions—operating systems apply standardized boundaries:

  • Microsoft Windows: Strictly adheres to the 128-partition limit for basic and dynamic GPT disks. Windows will not recognize or allow the creation of additional partitions beyond 128 on a standard GPT layout.
  • Linux: Does not have an inherent architectural limit of 128 partitions and can allocate larger partition arrays if configured, though standard tools (such as fdisk and gdisk) default to the standard 128-partition table size to maintain UEFI boot compatibility.

Advantages Over the MBR Layout

The standard GPT allocation resolves the fundamental limitations of the legacy Master Boot Record (MBR) system:

  • No Extended Partitions: MBR was restricted to four primary partitions, requiring complex workarounds like extended and logical partitions to create additional volumes. GPT treats all 128 entries as primary partitions.
  • Unique Identification: Every partition is assigned a Globally Unique Identifier (GUID), preventing drive-letter conflicts and mounting issues across different systems.
  • Redundancy and Reliability: Unlike MBR, which stores a single partition table at the beginning of the disk, GPT stores a primary partition table at LBA 1–33 and a backup (secondary) table at the end of the physical disk, preventing corruption from taking the entire partition structure offline.
